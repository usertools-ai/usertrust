# usertrust-openshell

**Not published. Work in progress.**

A supervisor middleware for [NVIDIA OpenShell](https://github.com/NVIDIA/OpenShell). It turns each LLM call a sandbox makes into a usertrust two-phase transaction:
1. estimate the cost;
2. place a hold;
3. allow or deny the call;
4. settle to actual usage from the response, with a hash-chained receipt.

The pure core, the hold journal, and the hold engine on the ledger. There is no gRPC server yet:

| Module | What it does |
|---|---|
| `routes` | Which provider route a request is. **Default-deny** for every other route, and for every host the config does not name; a pass-through entry is pinned to its host. |
| `gate` | The request gate. It refuses the request shapes v1 does not meter, bounds input tokens conservatively, and prices the hold. An **unpriced model is denied**, never billed at a fallback rate. It also returns the request mutations. |
| `settle` | Classifies a response: void, settle at the hold (body unreadable), or which body mode to read. |
| `usage` | Incremental usage parsers for Anthropic and OpenAI, JSON and SSE. Their result does not depend on how the body is split into units. |
| `hold-key` | The deterministic hold key from `(sandbox_id, request_id)`. |
| `journal` | The hold journal: one SQLite file per host (`node:sqlite`, WAL). It is the compare-and-set store that gives each hold **exactly one** terminal state:<ul><li>a caller wins only when exactly one row changed;</li><li>a busy lock **throws** and is never reported as a lost claim;</li><li>a reservation reads the debt, checks the headroom, places the hold and records it in **one** transaction;</li><li>each debt change applies once per ledger transfer;</li><li>the sweeper has a work list for each of its jobs.</li></ul>Every write transaction also takes an in-process lock, and in-transaction operations check a per-transaction token, so a call from another request can never run inside an open transaction. A claim commits before any ledger call: `writeTx` takes a synchronous body (an async body is refused, and its later rejection is absorbed rather than left unhandled). Only a reservation holds its transaction across a ledger call, and each such call has a deadline. Reads outside a transaction use a separate connection and see only committed rows. A reservation's ledger calls must use the transfer id derived from the hold id, so a retry after a lost commit can never place a second hold. A placement that fails may still have landed, so it is committed as `voiding` (the release path voids the derived id) rather than rolled back into an orphan. A placement must set a ledger-side timeout no later than the hold's `ttlAt`. A void that finds no transfer finalizes the hold only after `ttlAt` plus a grace, because an abandoned placement may still land; until then the hold stays in flight and is re-voided. A late settlement may finish from `expiring`: it and the sweeper's expiry race on one compare-and-set. The schema is versioned (now 4) and each readable version has an exact shape: every table and its columns, with triggers counted and SQLite's own `sqlite_*` internals ignored. A fresh file is one with no objects at all; an older shape is migrated in one transaction, and anything else is refused untouched. Each hold carries two deadlines: `admitBy`, the EARLIEST the ledger's own timeout can release it, and `ttlAt`, the latest. Admission is judged by `admitBy`: a retry of an `open` row, and a placement that answers, at or past it are refused (`hold_expired`), because the row is not proof the ledger hold is still live. The sweeper and the placement horizon count from `ttlAt`. A journal file written before `admitBy` existed is refused at open (`JournalSchemaError`). |
| `ledger` | The ledger port and its TigerBeetle implementation. Every transfer id is **derived** from the hold key and a role (`reserve`, `post`, `void`, `overage`, `late`), so a replay resubmits the same id and never moves money twice. Overage and late debits go to a per-budget **debt account** with no balance constraint, so they cannot be refused. |
| `engine` | The hold engine:<ul><li>**reserve**, atomic with the debt. The journal bounds both in-lock ledger calls. **Every account a settlement might touch is ensured before placement**: a budget id the debt account cannot be named for (`::` is reserved by core) is refused (`BudgetIdError`), and the debt account itself is ensured, so a colliding ordinary wallet refuses the reservation rather than stranding a posted hold. The placement has **one shared deadline** from one clock read: it must start by `placeBy` (the lock wait and the balance lookup included, or it is not placed: `PlacementWindowError`) and commits within one more deadline; the ledger's timeout starts at that commit, so `admitBy` is the start plus the lifetime and `ttlAt` is `placeBy` plus a deadline plus the lifetime. The hold's own reserve transfer, an orphan of a lost commit, does not count against its retry. The retry reaches the placement, the ledger refuses the replay, and the row is committed `voiding`, so the orphan is voided promptly;</li><li>**settle**: validate the intent against the hold (safe non-negative integers; `post` at most the hold; an overage only with the hold posted in full: `InvalidSettlementIntentError`), claim (with the intent) and record the overage's debt in the same transaction, so the next reservation sees it at once; then post, then the overage charge outside any transaction, then `settled`. A confirmed expiry reverses the debt with the `expired` transition. A duplicate **resumes** from the stored intent; a loser acts by state. If the hold expired first (the ledger confirmed it, or the sweeper claimed it), it is **late-settled**: never a post. The full actual amount is recorded once on the row with its debt, then charged to the debt account (`late`, or `late-retry` if that id was retired). A duplicate acts on the stored amount;</li><li>**release** for a non-2xx response or an ambiguous placement. A void is finalized by what the ledger answers: `voided`, `voided_expired`, or `voided_not_found` only past the placement horizon (until then the hold stays in flight and is released again). A hold the ledger reports as posted is an incident, never voided. A post or void id the ledger has RETIRED (an earlier attempt failed: TigerBeetle retires an id on `pending_transfer_not_found`) is answered by reading the hold back by its derived ids — posted, voided, never placed, or expired by its own timestamp past a skew margin — and anything still unconfirmed stays in flight, never a throw loop. A placement that lands after its `void` id was retired is voided at once under a second id, `void-late`; a debt charge whose id was retired (its first attempt failed, so nothing landed under it) is charged once under `overage-retry` / `late-retry`; a debit from a CLOSED debt account (`debit_account_already_closed`, measured on 0.17.9 to retire the id) is treated the same, and the charge does not re-ensure the account (the reservation ensured it), so a closed account reaches that answer on the first attempt; if both ids are retired and neither landed, the ledger refuses the charge for good — a terminal `debt_charge_failed` incident is recorded on the row (it is no longer in flight) and `DebtChargeFailedError` names both ids. The journal schema carries a version, and a file of any other version is refused at open.</li><li>**sweep**, on a timer and once at start: writes a heartbeat; expires every `open` hold past `ttlAt` plus a grace (claimed `open → expiring`, finished by what the void answers: `expired`, an incident if the ledger says posted or not found, or left in flight); replays every in-flight row (`settling` through the same intent choke point as any settlement, `voiding`, `expiring`; a row carrying an incident is never resumed); and charges every recorded, uncharged late settlement. One row's failure is reported and never stops the sweep. Finally it records every **missing audit event** (below).</li><li>**audit events**, with an audit port: every hold records, once each, `openshell.hold.reserved`, one terminal event (`settled`, `voided` or `expired_unsettled`) and, for a late settlement, `late_settlement`. "Once" is one critical section under the journal's write lock: the row's slot is checked; the chain is verified **from the journal's checkpoint** (the checkpoint's own line must still be there unchanged, every later line must parse, link and hash, the log must not end in a torn line, and the `.meta` head anchor must agree with the verified head — a chain that does not verify is refused, never read as "absent"); the event is found in that verified tail or appended; every hold event in the tail is absorbed into its row's empty slot; and the slot and the advanced checkpoint are written. A record therefore costs O(new events), not O(chain). The sweep re-verifies the whole chain up to the checkpoint at each engine instance's first sweep (in memory, so a restart always re-verifies) and then every `auditFullVerifyMs` (default one hour), streamed, off the request path. The checkpoint has three states — `unset`, `valid`, `broken` — and is NEVER cleared: a definite finding about verified history (by a record or the full verification) makes it `broken`, the checkpoint kept as the evidence; while `broken` every record is refused at once (admission included) and the detector raises `audit_chain_broken`; the only way back is `HoldEngine.resetAuditChain` — an operator reset that re-verifies the chain from genesis, appends a chained `openshell.audit.reset` naming both heads, and journals the reset. A refusal in the unverified tail, or an I/O error, changes nothing. A terminal or late event is recorded only after the hold's `reserved` event. The `reserved` event **fails closed**: an admission completes only once it is recorded, and is decided again from a read taken after that await (the row still `open`, before `admitBy`, its event recorded); a caller whose event failed releases the hold only if no other caller has since admitted it. A terminal or late event is recorded right after its transition, best-effort; one that fails is recorded by the next sweep. A row carrying an incident records no event: the incident is its record.</li></ul>|
| `detector` | The **independent** detector: a separate periodic check that reads the journal and writes nothing, so it does not share the sweeper's failures. It raises an incident for: a sweeper that never ran or whose heartbeat is stale; `open` holds, in-flight rows and uncharged late settlements overdue (two sweep intervals past the sweeper's own deadline); and every row carrying a recorded incident; and, with `auditEvents`, every `reserved`, terminal or late-settlement event still missing past the same bound (`event_missing_overdue`). A journal it cannot read is a distinct reading (`readable: false`), never zero counts. |
| `audit` | The audit port, and `VaultAudit`, its implementation on core's audit writer. `VaultAudit.open` takes the vault's audit lock **at open** (`lockAtCreate`). Its `record` verifies the chain **from the journal's checkpoint**: the checkpoint's line unchanged, every later line parsed, linked and hashed, no torn final line, and the `.meta` head anchor agreeing with the verified head. It then finds the event in that tail or appends it and reads the append back. Its `verifyFull` re-verifies genesis to the checkpoint, streamed. Verification, scan and append are one operation, serialized on the port, so a record that outlives its caller's deadline finishes before the next one reads. A chain with other `*.jsonl` segments is refused: core never writes one today. |
| `runtime` | `startRuntime`: **one process per vault, enforced at START.** It takes the vault's audit lock first, so a second live process fails there (`AuditWriterLockHeldError`) before it opens the journal, sweeps or replays. Then it opens the journal, builds the engine with the audit port, and runs one sweep (the replay at start). `close()` closes the journal and releases the lock. |
| `reasons` | Deny reason codes, checked against OpenShell's `^[a-z][a-z0-9_]{0,63}$`. |

## Spec gaps (decisions taken here, flagged for review)

- **No model maximum output.** The design holds a model's maximum output when a request sets no output limit, but core's pricing table has no such field. **Interim:** a request with no valid output limit is DENIED with `max_output_unbounded`. That's the only safe choice without a ceiling. A per-model maximum belongs in the pricing table.
- **No strict "is priced" check in core.** `getModelRates` silently falls back to a default rate, and its PREFIX match prices a variant at its base's row (`o3-pro` at `o3`, `gpt-4o-2024-05-13` at `gpt-4o`, `gpt-5.4-pro` at `gpt-5.4`) — up to 10× under. This slice adds core `isModelPriced`, which is true only for an EXACT table entry or an operator `customRates` entry; anything else is DENIED with `model_unpriced`. It is never billed at the fallback rate or a prefix's rate. `getModelRates` itself is unchanged.
- **Image bounds** come from the providers' documented formulas, not measurements.
  - Anthropic: 4,784 visual tokens per image, the high-resolution tier's cap for Claude 4.7 and later. Older models cap at 1,568, so they are over-held.
  - OpenAI tile models: base + 8 tiles. gpt-4o and gpt-4.1 are 1,445; gpt-5 and gpt-5.1 are 1,190; o1 and o3 are 1,275.
  - Every other OpenAI model, including gpt-4o-mini (up to 48,169 per image) and the patch-based models: 73,800. That is the 30,000-patch limit × the largest documented multiplier (2.46).
  - All three are configurable (`imageTokenMax`, `imageTokenMaxByModel`). Every image and tool bound in the config must be a non-negative safe integer, or `evaluateRequest` throws `GateConfigError` (the middleware fails, so the call is blocked): a bad value would lower the bound, and the config is refused rather than replaced by a default.
- **Two reason codes beyond the design's list:**
  - `content_unsupported`: a content part or input item v1 cannot bound, such as audio, a base64 PDF or a provider-run tool call in history. It is denied by allowlist, like tools.
  - `max_output_unbounded`: above.
- **Inline documents:** only a `text`-source document is bounded by its bytes. A `file` or `url` source is provider context. A base64 PDF is billed per page, so it is denied (`content_unsupported`).
- **Tiers priced above standard are DENIED, not counted** (`pricing_tier_unsupported`). Settlement has no tier input, so an admitted priority call would settle at standard rates: an under-charge, not a finding.
  - Anthropic: `speed` other than `standard` (fast mode), and `inference_geo` other than `global` (US-only is 1.1×).
  - OpenAI: `service_tier` `priority`, `fast`, `ultrafast` or `scale`. An absent or `auto` tier means the project's configured tier, which the gate cannot see, so it is pinned to `default` in the forwarded body. `flex` is cheaper and passes.
- **Top-level fields are allowlisted per route** (`parameter_unsupported`). A field the route's list does not name is denied. So is a documented field whose billing v1 does not bound: Anthropic `fallbacks`, `compaction`, `context_management`, `diagnostics`; OpenAI `audio`, `prediction`, `moderation`, `prompt_cache_options`, `prompt_cache_retention`, `context_management`, `access_programs`.
- **Known under-holds, documented rather than bounded:**
  - **1-hour cache writes.** Anthropic's 1-hour cache writes bill above the table's 5-minute cache-write rate, and the hold prices the cache-write tier at the table's rate.
  - **Long context.** OpenAI bills input above 272K tokens at a higher long-context rate; the hold and the settlement both use the table's standard rate.
  - **Regional endpoints.** OpenAI regional and FedRAMP endpoints carry a 10% uplift. Only `api.openai.com` is routed by default; an operator adding a regional host takes this on.
- **The forwarded body is the gate's own parse, re-serialized.** The provider reads exactly the document the gate checked, so duplicate keys cannot be read two ways, and the input bound is counted on those forwarded bytes.
- **Tool overhead.** A request with tools adds the provider's tool-use system prompt: Anthropic 1,024 tokens, above the largest documented figure of 804. OpenAI documents no fixed overhead; function definitions are billed as input and bounded by their bytes.
- **The input bound is held at its dearest tier.** Plain input, cache write or cache read, whichever an operator's rates price highest. Each tier is linear, so no split of the bound across tiers costs more.
- **Settlement uses the hold's rates.** The hold snapshots the `ModelRates` it was priced with, and settlement prices usage with that snapshot. Operator rates lowered between reserve and settle cannot settle the call below its hold's pricing. The returned `Hold` and its rates are frozen.
- **An Anthropic stream needs its final usage.** A `message_stop` with no `message_delta` usage settles at the hold (`no-final-usage`), not on `message_start`'s counts.
- **Streams must finish.** A stream without its route's terminal event settles at the hold (`usage_unreadable`, `truncated`):
  - Anthropic `message_stop`;
  - OpenAI chat `data: [DONE]`, settling on the LAST usage before it (an upstream reporting running counts sends cumulative usage, so the first report would under-charge). `stream_options` is an allowlist: only `include_usage`, which the gate sets itself, and only as a boolean. Any other key, `continuous_usage_stats` included, or a non-object is refused (`parameter_unsupported`), so a key a provider adds later is reviewed before it can change how usage is reported;
  - Responses `response.completed`, `.incomplete` or `.failed`. Responses settles on the terminal event's usage whenever that event carries one.
- **Split invariance** is checked exhaustively over every single cut point, every pair of cut points on a stride, and one-byte units, rather than with a property-testing dependency.
