---
title: trust()
description: The core API — wraps any LLM client with governed spend, audit, and policy.
---

`trust()` is the single entry point for the usertrust SDK. It takes any supported LLM client, wraps it in a JS Proxy, and returns a governed client where every API call becomes an audited, budget-enforced financial transaction.

## Signature

```typescript
async function trust<T>(client: T, opts?: TrustOpts): Promise<TrustedClient<T>>
```

`trust()` is async because it initializes the vault, loads config, connects to TigerBeetle (unless dry-run), and sets up the audit chain before returning the governed client.

## TrustOpts

```typescript
interface TrustOpts {
  configPath?: string;    // Path to usertrust.config.json
  proxy?: string;         // Deprecated — not implemented; setting this throws
  key?: string;           // Deprecated — proxy API key; unused because proxy throws
  budget?: number;        // Token budget override (in usertokens)
  tier?: string;          // Tier override (free | mini | pro | mega | ultra)
  dryRun?: boolean;       // Skip TigerBeetle — audit chain + policy still run
  vaultBase?: string;     // Vault directory override (default: process.cwd())
}
```

| Option | Default | Description |
|--------|---------|-------------|
| `configPath` | `.usertrust/usertrust.config.json` | Path to the config file. Resolved relative to `vaultBase`. |
| `proxy` | `undefined` | **Not implemented.** Setting this option throws. Use a local TigerBeetle or `dryRun` for enforcement. |
| `key` | `undefined` | **Not implemented.** API key for the removed proxy. Unused; `proxy` throws first. |
| `budget` | Config value or `10_000` | Total usertoken budget for this client. Overrides the config file value. |
| `tier` | `"mini"` | Tier classification. Overrides the config file value. |
| `dryRun` | `false` | Skip TigerBeetle entirely. Also enabled by `USERTRUST_DRY_RUN=true` env var. Useful for CI and testing. |
| `vaultBase` | `process.cwd()` | Base directory containing the `.usertrust/` vault. |

<Callout type="info">
The internal `_engine` and `_audit` options exist for testing only. They inject mock subsystems and are not part of the public API.
</Callout>

## TrustedClient\<T\>

```typescript
type TrustedClient<T> = T & { destroy(): Promise<void> };
```

The returned client has the exact same shape as the original LLM client, plus a `destroy()` method. You call the same methods you already use (`messages.create`, `chat.completions.create`, etc.) and get governed responses back.

<Callout type="warn">
Always call `destroy()` when you are done with the client. Without it, the process will hang due to open TigerBeetle connections and file locks.
</Callout>

## Return Value

Every intercepted LLM call returns `{ response, receipt }` instead of the raw provider response:

```typescript
const { response, receipt } = await client.messages.create({
  model: "claude-fable-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Hello" }],
});
```

The `response` is the original, unmodified provider response. The `receipt` is a `TrustReceipt` with governance metadata.

## TrustReceipt

```typescript
interface TrustReceipt {
  transferId: string;         // Universal join key across ledger, audit, receipts
  cost: number;               // Actual cost in usertokens
  budgetRemaining: number;    // Remaining budget after this call
  auditHash: string;          // SHA-256 hash of the audit event
  chainPath: string;          // Path to the audit chain JSONL file
  receiptUrl: string | null;  // Verify URL (null in local mode)
  settled: boolean;           // true if POST succeeded; false on failure mode 15.1
  model: string;              // Model used for the call
  provider: string;           // "anthropic" | "openai" | "google"
  timestamp: string;          // ISO 8601 timestamp
  auditDegraded?: boolean;    // true if audit write failed after POST (mode 15.3)
}
```

The `transferId` is the universal join key. Use it to correlate entries across the TigerBeetle ledger, the audit chain, and receipt files.

## Provider Detection

`trust()` identifies the LLM SDK by structural shape (duck typing). It never imports provider SDKs directly.

| Provider | Detection Shape | Intercepted Method |
|----------|----------------|-------------------|
| Anthropic | `client.messages.create` exists | `messages.create()` |
| OpenAI | `client.chat.completions.create` exists | `chat.completions.create()` |
| Google | `client.models.generateContent` exists | `models.generateContent()`, `models.generateContentStream()` |

If the client does not match any known shape, `trust()` throws an error at initialization time.

On a Google client the other billable methods are refused rather than passed through: `models.embedContent`, `generateImages`, `editImage`, `upscaleImage`, `generateVideos`, `recontextImage`, `segmentImage`, `chats.create`, `live.connect`, `live.music.connect`, `batches.create`, `batches.createEmbeddings`, `interactions.create`, `tunings.tune`, `caches.create`, `caches.update`, `fileSearchStores.uploadToFileSearchStore` and `fileSearchStores.importFile` reject with a `PolicyDeniedError` naming the method (carrying the `auditEventHash` of the `policy_denied` event it records) before the SDK is called. Either method with automatic function calling (a callable tool in `config.tools`, AFC not disabled) is refused the same way for now, because the SDK then makes one provider request per tool round and usertrust cannot yet meter every round: set `config.automaticFunctionCalling.disable: true` and run the tool calls yourself. Calls that are not billed (`models.countTokens`, `models.list`, `caches.get`, `files` and the like) pass through ungoverned.

## Streaming

Streaming is transparent. When you pass `stream: true` to the provider, usertrust returns a `GovernedStream` that yields chunks identically to the native stream. A streaming call carries two receipts:

- `receipt`, beside `response`, is **provisional**. The stream has not run yet, so it is priced at the estimate and has `settled: false`.
- `response.receipt` is a promise of the **settled** receipt. It resolves when the stream ends, or when you stop reading early (a `break`), in which case the usage consumed so far is settled.

Google's `models.generateContentStream()` takes no `stream` flag and returns no envelope: like the SDK's own method it resolves to the stream itself, and the settled receipt is `stream.receipt`. Everything below applies to it the same way.

```typescript
import { AuditDegradedError } from "usertrust";

const { response, receipt: provisional } = await client.messages.create({
  model: "claude-fable-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Write a poem" }],
  stream: true,
});
// provisional.settled === false

let streamError: unknown;
try {
  for await (const chunk of response) {
    try {
      process.stdout.write(chunk.delta?.text ?? "");
    } catch (err) {
      // Your own code threw. Stopping early is not a stream failure: what was
      // consumed settles and is charged, as with any `break`.
      console.error(err);
      break;
    }
  }
} catch (err) {
  streamError = err; // the stream itself threw (or, under audit.failClosed, refused)
}

try {
  const receipt = await response.receipt; // settled: true
  console.log(`Cost: ${receipt.cost} UT`);
} catch (err) {
  if (err === streamError && !(err instanceof AuditDegradedError)) {
    // The stream failed mid-way: its hold was voided, nothing was charged.
  } else {
    // AuditDegradedError (audit.failClosed), or another settlement error:
    // settlement ran, so the work may be billed. Do not simply retry it.
  }
}
```

The billing claim is made in one place only: the catch around `await response.receipt`, which covers none of your code. The loop's body has its own try, so a throw there is never mistaken for a stream failure.

**When a stream fails mid-way and its iteration throws** (a cut connection, or a provider error event that the SDK throws, as Anthropic's and OpenAI's `chat.completions` streams do), `response.receipt` rejects with that same error object. The budget hold is voided, not charged, and the audit chain records a `stream_partial_delivery` event with the chunks delivered and the tokens counted before the failure. A throw from your own loop body is NOT a stream failure: the loop exits early, and the usage consumed so far settles and is charged, as with a `break`.

**An OpenAI Responses `error` event does not throw.** The OpenAI SDK yields a `responses.create({ stream: true })` error event (`type: "error"`) as an ordinary chunk, so the stream ends and settles like any completed stream: at the estimate when no usage arrived. It is charged. Check each chunk's `type` to tell it apart. Whether such a stream should be charged is an open settlement question.

**A rejected `response.receipt` does not always mean nothing was charged.** It rejects with either the iteration's own error (the same object: the hold was voided), or, under `audit.failClosed`, an `AuditDegradedError`: settlement already ran (the charge posted, or its POST failed and the outcome is ambiguous: it may still post), then the audit write failed. Either way the work may be billed, so retrying it can charge it twice. `AuditDegradedError` is exported from `usertrust`, so test `err instanceof AuditDegradedError` to tell the two apart. Any other settlement error also rejects `.receipt` alone, after settlement claimed the call, so treat it like the audit refusal: the work may be billed.

**Under `audit.failClosed`, that refusal also ends the iteration** of a `messages.create`, `chat.completions.create`, `responses.create` or Google `models.generateContentStream` stream: the loop's last step, or the `break` that ends it early, throws the `AuditDegradedError`. Settlement has already run, and nothing is voided. Only `AuditDegradedError` ends the iteration: any other settlement error rejects `.receipt` alone, and the loop ends cleanly. If your loop body throws, the loop throws YOUR error, not the audit refusal (JavaScript keeps the original throw), so await `.receipt` to see a refusal. A `messages.stream()` caller must await `.receipt` under `failClosed`: its iteration and `finalMessage()` do not carry the audit refusal.

**Skipping `await response.receipt` never crashes the process:** a rejected receipt is never left as an unhandled rejection. On `messages.create`, `chat.completions.create`, `responses.create` and `models.generateContentStream` streams, a stream failure reaches the iteration, and so does an audit refusal under `failClosed` when the loop ends normally or with a `break` (not when your loop body throws); any other settlement error reaches only `.receipt`. A `messages.stream()` caller under `failClosed` hears of an audit refusal only from `.receipt`.

Token counts are accumulated per-provider from stream chunks:
- **Anthropic**: `message_start` (input tokens), `message_delta` (output tokens)
- **OpenAI**: `usage` field on the final chunk
- **Google**: `usageMetadata` field, read from the latest chunk that carries it (each one is a running total, so nothing is summed)

## Examples

### Anthropic

```typescript
import Anthropic from "@anthropic-ai/sdk";
import { trust } from "usertrust";

const client = await trust(new Anthropic(), {
  budget: 50_000,
  dryRun: true,
});

const { response, receipt } = await client.messages.create({
  model: "claude-fable-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Explain double-entry accounting" }],
});

console.log(response.content[0].text);
console.log(`Cost: ${receipt.cost} UT, remaining: ${receipt.budgetRemaining}`);

await client.destroy();
```

### OpenAI

```typescript
import OpenAI from "openai";
import { trust } from "usertrust";

const client = await trust(new OpenAI(), { budget: 30_000 });

const { response, receipt } = await client.chat.completions.create({
  model: "gpt-5.6-sol",
  messages: [{ role: "user", content: "What is a Merkle tree?" }],
});

console.log(response.choices[0].message.content);
console.log(`Settled: ${receipt.settled}, hash: ${receipt.auditHash}`);

await client.destroy();
```

### Google

```typescript
import { GoogleGenAI } from "@google/genai";
import { trust } from "usertrust";

const client = await trust(new GoogleGenAI({ apiKey: "..." }), {
  budget: 20_000,
});

const { response, receipt } = await client.models.generateContent({
  model: "gemini-2.5-pro",
  contents: "Explain hash chains",
});

console.log(response.text);
console.log(`Transfer: ${receipt.transferId}`);

// Streaming: resolves to the stream itself, with the settled receipt on it
const stream = await client.models.generateContentStream({
  model: "gemini-2.5-pro",
  contents: "Explain hash chains",
});
for await (const chunk of stream) process.stdout.write(chunk.text ?? "");
const settled = await stream.receipt;
console.log(`Settled: ${settled.cost} UT`);

await client.destroy();
```

### Streaming (Anthropic)

```typescript
import Anthropic from "@anthropic-ai/sdk";
import { trust } from "usertrust";

const client = await trust(new Anthropic(), { budget: 50_000 });

const { response } = await client.messages.create({
  model: "claude-fable-5",
  max_tokens: 2048,
  messages: [{ role: "user", content: "Write a short story" }],
  stream: true,
});

try {
  for await (const event of response) {
    if (event.type === "content_block_delta") {
      process.stdout.write(event.delta.text);
    }
  }
  const receipt = await response.receipt;
  console.log(`\n\nCost: ${receipt.cost} UT`);
} catch (err) {
  // What this error cost, and how to tell, is under Streaming above: this
  // catch also covers your own code in the loop, whose throw is charged.
}

await client.destroy();
```
